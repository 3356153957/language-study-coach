# language-study-coach 产品找茬记录

这轮按手机端第一次打开、继续练习、查看进展、回顾错题四条路径检查。问题按“会不会让用户迷路或等待”排序。

| # | 发现的问题 | 修复结果 |
|---|---|---|
| 1 | 首页曾把模型、规则和能力分析放在学习入口前面，用户看不到下一步。 | 首页改成任务优先：继续练习、专项入口、最近练习、能力摘要。详细说明移到详情页。 |
| 2 | 练习中切换目标后，页面可能让人误以为会切换当前这一轮。 | 首页在存在活动练习时明确显示“当前练习：目标”，继续卡片始终指向正在进行的那一轮。 |
| 3 | “开始综合练习”点击后缺少即时反馈，容易重复点击。 | 保留独立准备页、忙碌状态和自动进入；请求期间按钮禁用，并显示正在准备第一题。 |
| 4 | 首页统计的“本周”容易被误解为自然周，且没有说明统计口径。 | 改为“近 7 天学习”和“近 7 天练习”，按用户时区统计。 |
| 5 | 能力页一上来就是一整段 AI 长文，关键信息被淹没。 | 首屏只显示等级和摘要，长总结改为“查看教练总结”折叠内容。 |
| 6 | 只有 A2/B1 文字，没有能力之间的相对进度。 | 每项能力增加轻量级进度条；仍保留“待积累”，避免把它伪装成精确分数。 |
| 7 | 导航只靠颜色区分当前页面，辅助技术无法判断位置。 | 当前导航按钮增加 `aria-current="page"`，移动端与桌面端共用。 |
| 8 | 普通首页请求会携带完整历史、背景和题目答案，历史一多就浪费内存。 | 常规请求改为 compact 摘要；背景与已结束轮次不下发，详情按需读取。 |
| 9 | 错题页一次加载所有错题，长记录会拖慢页面。 | 错题接口按 20 条分页，上一页/下一页按需读取。 |
| 10 | 统计遍历和考试证据收集会复制整段历史，且夏令时附近可能出现重复日期。 | 改为从最新记录反向读取所需样本，按用户时区的日历日期生成近 7 天。 |
| 11 | 聊天练习第一次打开也沿用“滚到最新消息”的逻辑，首题顶部可能被裁掉。 | 首题从顶部开始，完成作答后才自动锚定到最新反馈。 |

## 验证

- `npm test`：38 项通过。
- `npm run build`：Vite 构建通过。
- `npm run ios:sync`：Capacitor 资源同步通过；Windows 没有 Mac，因此没有声称已编译或签名 IPA。
- 手机 390×844 实测：首页、底部导航、能力详情、折叠总结均可见；当前本地服务重启后可通过“重新连接”恢复。
- 压力脚本使用 1,000 轮/5,000 题的合成数据：完整历史响应约 12.86 MB，compact 响应约 2.5 KB；事务复制额外堆内存峰值由约 32.63 MB 降至约 0.25 MB。该脚本不代表真实 AI 延迟，也不等于整个 iOS App 的 RSS。
